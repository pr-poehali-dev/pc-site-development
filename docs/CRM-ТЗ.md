# CRM WhiteFriday — техзадание (черновик)

> Файл-память по проекту. Обновляем по ходу обсуждения.
> Последнее обновление: 2026-08-05

## Общая идея
Единая экосистема **сайт — Telegram-бот — CRM**. CRM живёт внутри существующей админки как общая система.
Данные пока НЕ переносим — строим пустой скелет, наполним позже.
Вкладку «Калькулятор» (таблица просчётов) не трогаем — внедрим отдельно позже.

## Порядок сборки (предложен, ждёт подтверждения)
Склад → Заказы → Финансы → Аналитика → Бот.
Новые разделы строим рядом с текущими, старое не ломаем.

---

## 1. Пользователи и права
- Права НЕ разграничиваем: у всех админов одинаковый полный доступ, включая историю движения средств и комплектующих.
- За главным админом (владелец) — инструмент добавления новых админов.
- Каждый админ связывает учётку админки со своим Telegram. Если не связана — визуальная метка в карточке пользователя.
- Индикатор Online/AFK и «последняя активность» — оставляем, если не тяжело по нагрузке.

### Открыто
- Механика привязки ТГ: одноразовый код от бота или ручной ввод @username.
- Что админ может делать в боте (просмотр заказов, смена статусов, уведомления).
- Уведомления в ТГ: всем или только ответственному по заказу.
- Закрепляем ли за главным админом ещё и удаление пользователей + правку справочников.

---

## 2. Заказы
Три типа: **ПК**, **Комплектующие**, **Работы**.
У каждого типа обязательно: внутренние комментарии между сотрудниками + фотографии (лимит 10 на заказ, без категорий, без флага «показывать клиенту»).

### Статусы ПК
в закупке → ожидаем поставки → ожидание сборки → в сборке → на тестах → готов к выдаче → передан в доставку
+ добавляем: выдан, отказ, гарантия.

### Статусы (предложены, ждут подтверждения)
- Комплектующие: Новый → В закупке → Ожидаем поставки → Поступил на склад → Готов к выдаче → Выдан → Отказ
- Работы: Новый → Принято в работу → Диагностика → Ожидание запчастей → Ожидание решения клиента → В работе → Готов к выдаче → Выдан → Отказ

### Поля и поведение
- «Заказанные компоненты» — свободный текст строками.
- Ссылка на чат — URL-поле (Авито, ТГ, ВК).
- Юр. лицо, «с печатью», обеспечительный платёж — переносим.
- Нумерация: сквозная. Сейчас не включаем, т.к. на новую CRM ещё не переходим.

### Открыто
- Формулировки статусов для клиента: как есть или упрощённые 4 («Заказ принят» → «Комплектующие в пути» → «Собираем и тестируем» → «Готов к выдаче»).
- Комментарии — лента с автором/датой или одно поле-заметка.
- Фото только на заказ или ещё и к каждому комментарию.

---

## 3. Склад
- Категории комплектующих (БП, видеокарта, СЖО, кулер белый/чёрный и т.д.) — редактируемый справочник.
- Источник/поставщик (WB, DNS, Скупка, Trade-in, Авито) — тоже редактируемый справочник.
- Позиции без серийника принимаются пакетно (количество в одной строке).
- **Списание**: компонент списывается в момент перемещения со склада в заказ, и возвращается обратно при замене детали.
- У позиции нужно поле «гарантия производителя» — уходит в гарантийный талон.

### Идея на потом (напомнить после скелета)
**Отрицательные резервы**: при новом заказе система сама подсказывает, чего не хватает и что нужно закупить.

### Открыто
- Разрешаем ли добавлять в заказ компонент, которого нет на складе («в минус»).
- Фиксируем ли причину замены детали (брак / клиент передумал / нет в наличии).
- Схема гарантии (предложена): позиция → «Отправить в гарантию» → раздел «Гарантия» со статусами Отправлено поставщику → На проверке → Заменено / Возврат денег / Отказ. При «Заменено» вводим новый серийник, позиция возвращается на склад. Деньги при возврате — приход на счёт.

---

## 4. Финансы
- Аванс по заказу автоматически создаёт доход.
- Списание компонентов и расходы работают внутри карточки заказа.
- Долговые счета — обычные счета с отрицательным балансом (берём в долг у коллег/сотрудников).
- Активы = склад по закупке + балансы счетов + готовые боксы.
- Внутренние переводы НЕ попадают в доходы/расходы отчёта.
- Удаление операции — мягкое, в «Историю удалений», с возможностью восстановить.

### Оплата заказа
Модалка «Внесение оплаты»: сумма заказа / внесено / к оплате.
Можно добавить несколько способов оплаты сразу, у каждого:
- Способ оплаты: Наличными, Переводом, Картой через терминал, СБП, Картой на сайте, СБП на сайте, Тинькофф рассрочка, Тинькофф кредит, Яндекс Сплит, Расчётный счёт
- Куда поступают деньги (получатель): Денис, Анастасия, Никита, Тимофей, Алексей, Наличные, Расчётный счёт, Анастасия долг, Анастасия кредитка, Светлана долг, BeGraphics долг, Артур
- Сумма оплаты

### Открыто
- Расход по закупочной цене конкретной позиции (по серийнику)?
- Маржа = сумма заказа − закупка списанных компонентов; работа/сборка — отдельная строка дохода без себестоимости?
- Обеспечительный платёж при отказе → становится доходом, кнопка «Отказ» предлагает это?
- Список способов оплаты — редактируемый админом?

## 5. Аналитика
- Блок «Маржинальность» из аналитики **убираем** (непонятная логика).
- **Заработано** = маржинальность со всех проданных ПК + комплектующих + работ − расходы.
- Отдельный блок: заработок по ПК / комплектующим / работам раздельно.
- График 3 — динамика заказов по месяцам. График 4 — доходы/расходы по месяцам.
- PDF-отчёт по аналитике — откладываем на потом.

Существующие блоки: ПК заказано, ПК выдано, Расходы, Доходы, Баланс, Заработано, блок «Комплектующие» (заказано/выдано), расходы по категориям и подкатегориям (список + donut-чарты).

## 6. Документы (PDF)
Генерятся из карточки заказа, печать и подписи вшиты в шаблон.

### Обеспечительный платёж
Заголовок + номер заказа, дата заказа, дата выдачи, внесено средств, остаток к оплате, таблица наименований, полная стоимость, условие оплаты остатка, реквизиты магазина, юридические пункты, печать.

### Гарантийный талон
Дата выдачи, таблица: Тип / Наименование / Серийный номер / Гарантия (по каждой позиции), сумма заказа, полный текст гарантийных условий, ИНН, реквизиты, поля подписей.
Гарантия от магазина — 1 год; 2 года при условии ежегодного ТО.
Сроки гарантии клиенту (модалка): 14 дней, 31 день, 180 дней, 365 дней, 2 года, 3 года, 5 лет, 7 лет, 10 лет + чекбоксы «Доп. гарантия при ТО 2 года» и «Доп. гарантия при ТО 3 года».

### Открыто
- Срок гарантии по компоненту — автоматом из склада или руками?
- Подтверждение схемы генерации PDF.
- Номер в талоне (540) и обеспечительном (571) — один и тот же номер заказа?
- Скан печати пользователь пришлёт позже.

## 7. Telegram-бот
- Клиентская часть — в существующем боте.
- Клиент вводит номер заказа: 3 попытки, затем таймаут на 1 час с сообщением «уточните номер заказа у менеджера».
- Автоуведомление клиенту при смене статуса, если он раньше запрашивал заказ.

---

## 8. График работ
Календарь по месяцам, слева список сотрудников.
Тип события: Рабочий день (синий), Отсутствовал (красный), Выходной (зелёный), Удалённая работа (фиолетовый).
Время работы (например 10:00—19:00). Порядок: выбрать сотрудника → тип события → кликать по дням календаря.
Снизу «Сводка по сотрудникам»: рабочих дней / пропусков / выходных / удалённой работы.
Кнопки: назад/вперёд по месяцам, «Сегодня», «Отмена».
Период + кнопка «Скачать PDF-отчёт».
Проставляет админ вручную.

---

## 9. Панель управления (дашборд)
- Задачи сотрудников (фильтры Все / Активные / Готово, кнопка «Создать»; колонки: Задача, Исполнитель, Срок, Статус).
- Новости компании.
- Таблица заказов: № / Доставка / Статус доставки / Выдача / Статус / Оплата / Заказаны / Компоненты.
  Фильтры: Статус, Последовательность сборки (по дате выдачи), Поиск (ФИО / почта / телефон).
- Боковая панель заказа: основная информация (клиент, телефон, выдача, заказ, сумма, внесено), «Открыть чат», Доставка (способ, стоимость, приоритет, получить), Примечание, Компоненты с чекбоксами.
  Кнопки: Оплата, Выдан, К заказу, Гарантия.
